# 모두 집으로 제품 설계

## 귀가 계획

- 운전자의 집을 최종 목적지로 두고 동승자의 하차와 생활 볼일을 경유 순서로 구성
- 차에서 내린 뒤의 대중교통·보행까지 포함해 사람별 도착시간을 비교하는 흐름
- 지인과 함께 타는 날에는 함께 귀가, 혼자 운전하는 날에는 가는김에를 진입점으로 사용

## 함께 귀가와 가는김에

- 출발 전에 동승자가 초대 링크나 QR로 목적지와 이동 조건 입력
- 차량에서 허용 추가시간과 사람별 귀가 계획 비교
- 픽업·장보기를 더하면 전원의 도착시간을 다시 계산
- 조건을 넘는 볼일은 마지막 하차 뒤로 옮기거나 보류
- 확정한 목적지와 경유 순서를 차량 내비로 전달
- 동승자는 하차 뒤 휴대폰에서 남은 이동 확인

## 혼자 가는김에

- 픽업과 장보기 중 최대 두 건을 선택하고 마감·체류시간에 따라 순서 비교
- 장보기는 일반 매장 방문을 기준으로 설계
- 픽업은 사용자가 수령 준비를 확인한 항목을 대상으로 구성

## 범위

| 항목 | 기준 |
| --- | --- |
| 인원 | 운전자 1명, 동승자 최대 2명 |
| 동승자와 볼일 | 한 이동에 운전자 볼일 1건 |
| 혼자 볼일 | 한 이동에 최대 2건 |
| 지역 | 수도권 일부 |
| 하차 후보 | 5~10곳을 선정해 차량 접근·보행 연결 확인 |

## 계산 기준

- 추가시간은 우회 주행, 주차 후 보행과 매장 체류시간을 합산
- 함께 귀가에서는 전원의 필수 조건을 먼저 충족
- 하차 뒤의 볼일은 이미 내린 사람의 귀가시간에 포함하지 않음
- 조건을 충족하는 계획이 없으면 해당 조건과 이유 표시
- 하차·수령·장보기 완료는 사용자의 확인으로 처리

## 화면 구성

| 화면 | 역할 |
| --- | --- |
| 차량 | 귀가 조건 입력, 계획 비교, 경유 순서 확인, 진행 안내 |
| 동승자 휴대폰 | 목적지 입력, 개인 조건 수정, 하차 후 이동 확인 |

- 차량과 휴대폰은 같은 버전의 이동 계획을 공유
- 목적지나 조건이 바뀌면 갱신한 계획을 기준으로 도착시간과 경유 순서를 표시

## 내비 연동 설계

| 역할 | 연결 대상 |
| --- | --- |
| 운전자 목적지 조회 | NaviHelper `getDestinationInfo`와 결과 이벤트 |
| 목적지·경유지 전달 | `requestRouteWithWaypoints`, `requestRoute` |
| 탐색 결과 처리 | `NaviHelperEventListener` |
| 주행 중 입력 제한 | `CarUxRestrictions` |

- 화면에서는 `NavigationGateway`에 목적지와 경유 순서를 전달
- SDK 타입과 권한 처리는 어댑터에서 담당
- `RouteRequestResult.Requested`는 요청 접수로 처리하고 안내 시작은 SDK 이벤트와 목적지·경유지 상태로 확인
- 지원 경유지 수, 권한과 이벤트 범위는 Pleos AVD에서 검증

## 경로 데이터

- 하차 후보마다 출처·확인일과 차량 접근·보행 연결 정보를 기록
- 경로 조회시각, 체류시간 가정과 시간표 반영 여부 표시
- 정적 대중교통 예상시간과 실시간 대기·막차 정보를 구분
- 외부 API는 호출 조합, 표시, 캐시, 보관과 상용 이용 조건을 확인해 선택

## 평가 기준

- 같은 출발지·시각·목적지에서 기존 내비와 대중교통 앱으로 고른 계획과 비교
- 결정시간, 운전자 추가시간, 사람별 전체 이동시간과 환승 횟수 측정
- 함께 귀가에서는 계획 채택 여부, 가는김에에서는 볼일 완료와 다음 귀가의 재사용 여부 확인
