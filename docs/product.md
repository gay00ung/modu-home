# 모두 집으로 제품 설계

동승자를 내려주면서 픽업이나 장보기도 하려면, 운전자의 우회시간과 각 사람의 도착시간을 함께 판단해야 한다
모두 집으로는 운전자 집을 마지막 목적지로 고정하고, 하차와 볼일의 가능한 순서를 비교해 이 결정을 돕는다

## 두 가지 귀가 흐름

| 진입점 | 구성 | 비교 기준 |
| --- | --- | --- |
| 함께 귀가 | 동승자 1~2명, 운전자 볼일 0~1건 | 사람별 집 도착과 운전자 추가시간 |
| 가는김에 | 픽업·장보기 최대 2건 | 집 도착, 추가시간과 볼일 조건 |

차량의 입력 화면에서 흐름을 선택하고, 진행 중인 계획은 같은 흐름에서 이어간다
동승자가 있는 날에도 볼일을 더할 수 있으며, 하차와 볼일을 하나의 전체 순서로 보관한다

## 함께 귀가 입력

- 현재 출발지는 NaviHelper가 제공한 차량 위치 사용
- 운전자 집과 동승자별 집 앞 하차 장소를 저장 장소·최근 목적지에서 선택
- 각 동승자가 집 앞에서 안전하게 정차한 차에서 내려 바로 귀가할 수 있는지 직접 확인
- 볼일 없음·픽업·장보기 중 하나를 선택하고 볼일 장소와 체류시간 설정
- 체류시간은 5·10·15분, 허용 추가시간은 10·20·30·60분 버튼으로 선택
- 픽업은 수령 준비 여부를 추가 확인

하차 후 이동 0분은 사용자가 집 앞 직접 하차를 확인한 조건이다
대중교통이나 도보 경로를 자동으로 조회한 결과로 취급하지 않는다
정차와 하차 연결 확인의 출처·시각을 함께 저장하고, 장소를 바꾸면 이 확인을 초기화한다
확인하지 않은 하차 장소는 적합하다고 가정하지 않으며 계획 조건 위반으로 표시한다

## 계획 계산

- 모든 방문 순서를 열거하고 운전자 집 직행 경로도 별도로 조회
- 동승자 2명과 볼일 1건이면 세 정차의 여섯 순서를 비교
- 구간별 도로 주행시간을 분 단위로 올림하고 동승자별 하차 정차 1분 합산
- 볼일에는 매장 체류와 주차 지점에서 매장까지의 왕복 보행시간 합산
- 운전자 추가시간은 전체 주행·정차·체류·보행시간에서 집 직행시간을 뺀 값으로 계산하고 최솟값은 0분으로 처리
- 동승자 도착은 해당 하차까지의 주행·앞선 정차·본인 하차 정차시간으로 계산
- 이미 내린 사람의 도착시간에는 이후 볼일이나 다른 동승자의 하차시간을 더하지 않음
- 허용 추가시간과 픽업 준비 등 필수 조건을 충족한 계획부터 표시
- 가능한 계획은 운전자와 동승자의 소요시간 합계, 운전자 추가시간 순으로 정렬

추가시간이 한도를 넘으면 초과한 분과 이유를 표시하고 출발을 막는다
도메인은 입력된 사람별 도착 마감·탑승시간 한도와 볼일 마감도 같은 방식으로 검사한다
차량 기본 화면은 장소와 프리셋 선택으로 구성한다

비교 시각과 실제 출발 시각을 구분한다
출발 버튼을 누르면 아직 유효한 도로 응답을 사용해 현재 시각으로 도착·마감을 다시 계산한다
이때 원래 경로 조회시각과 출처는 유지하며, 응답의 유효시간을 늘리지 않는다
5분이 넘은 응답은 현재 위치에서 다시 조회한다

## 세 정차를 안내하는 방법

차량 내비에는 경유지를 한 번에 최대 두 곳 전달한다
앱은 세 정차를 포함한 전체 계획을 유지하고, 정차 완료를 확인할 때 다음 안내에 필요한 최대 두 곳을 연결한다

전체 순서가 `하차 A → 하차 B → 장보기 E → 운전자 집`인 경우

| 확인한 완료 | 내비 경유지 | 최종 목적지 |
| --- | --- | --- |
| 출발 전 | A → B | 운전자 집 |
| A 하차 완료 | B → E | 운전자 집 |
| B 하차 완료 | E | 운전자 집 |
| E 장보기 완료 | 없음 | 운전자 집 |

처음 전송한 안내에는 E가 들어 있지 않으므로 확인 화면과 진행 화면에서 단계별 안내임을 설명한다
정차 완료 후 남은 경유 순서와 운전자 집이 실제 내비에 반영됐는지 다시 읽어 확인한다
다음 안내 반영이 실패해도 이미 확인한 하차·볼일 완료 기록은 되돌리지 않는다
기존 안내가 다른 경로로 바뀌었다면 현재 목적지와 새 순서를 보여주고 사용자가 변경을 확인한 뒤 요청한다

내비에서 앞 경유지가 사라졌다는 사실만으로 실제 하차나 볼일 완료를 기록하지 않는다
현재 길안내가 해당 단계의 앞 경유지 1~2곳만 제외한 순서와 정확히 맞으면, 정차 상태에서 사용자가 실제 완료를 확인한 뒤 다음 단계로 이어갈 수 있다
확인창에 대상 장소와 하차·볼일 종류, 실제 내비의 남은 경유지와 집을 표시하며 두 곳은 모두 마쳤을 때 함께 확인한다
모든 정차를 마친 뒤에는 집 도착을 별도로 확인해 귀가를 마친다

## 혼자 가는김에

- 픽업과 장보기 중 최대 두 건을 선택하고 체류·보행·마감 조건으로 순서 비교
- 장보기는 일반 매장 방문, 픽업은 사용자가 수령 준비를 확인한 방문으로 처리
- 동승자 하차 없이 선택한 볼일과 집을 차량 내비에 전달
- QR·링크로 받은 볼일은 내용을 검토하고 같은 종류의 기존 볼일에 반영

휴대폰은 볼일 제안 작성과 전달에 사용한다
차량은 받은 제안의 장소·체류·마감·준비 상태를 사용자가 확인한 뒤 적용하며, 앱이 차량과 휴대폰 사이의 실시간 계획 동기화를 전제로 삼지 않는다

## 저장과 복원

- 함께 귀가 입력, 모든 순서의 도로 응답, 선택한 계획과 진행 단계를 기기 안에 저장
- 하차·볼일 완료 시각과 실제 확인한 내비 안내, 다음에 반영할 안내를 구분해 보관
- 내비 요청 전에 진행 상태 저장 결과를 확인하고 저장 실패 시 새 안내 전송 중단
- 재시작하면 장소·구간·지도 버전·선택 순서·완료 개수를 다시 검증
- 비교·확정 전 응답이 오래됐으면 입력으로 돌아가 재조회
- 진행 중·완료 기록은 응답이 오래돼도 보존하고 진행 중인 내비는 재확인 대기로 복원
- 복원 자체가 경로를 전송하거나 기존 내비를 변경하지 않음
- 손상된 기록은 입력 단계로 복귀하며 최대 저장 크기는 256KiB로 제한

## 화면과 책임

| 구성 | 역할 |
| --- | --- |
| 차량 화면 | 장소·프리셋 선택, 사람별 계획 비교, 전체 순서 확인, 정차 완료 기록 |
| 동승자 휴대폰 | QR·링크를 통한 볼일 제안 작성·전달 |
| `ModuHomeApp` | 화면 상태 소유, 저장 결과 반영과 모드 선택 |
| `feature/shared` | 함께 귀가 입력 검증, 전체 경로 조회와 단계별 내비 작업 조정 |
| `core/shared` | 순서 열거, 시간·조건 계산과 완료 상태 전이 |
| `data` | NaviHelper·OSRM·로컬 저장 형식 변환 |

SDK 타입은 어댑터에 두고 계산 코드와 화면에는 전달하지 않는다
차량 입력은 `CarUxRestrictions`를 따르며 상태를 알 수 없거나 제한 중이면 장소·계획 변경과 완료 확인을 잠근다

## 경로 출처와 평가

비교 시간은 OpenStreetMap 도로망과 OSRM 자동차 프로필에 따른 예상값이며 실시간 교통은 포함하지 않는다
각 응답의 조회시각과 지도 버전을 보관하고, 서로 다른 버전이나 일부 순서만 확보한 결과를 비교에 섞지 않는다
하차 확인과 체류·보행시간은 사람이 선택한 조건으로 도로 응답과 구분한다

- 같은 출발지·시각·목적지에서 사용자가 직접 고른 순서와 비교
- 결정시간, 운전자 추가시간과 사람별 전체 소요시간을 측정
- 하차 뒤 볼일이 이미 내린 사람의 도착시간을 바꾸지 않는지 확인
- SDK에서 확인한 목적지·경유 순서와 앱의 해당 안내 단계를 대조
- 재실행·연결 실패 후 완료 기록과 남은 정차가 유지되는지 확인
- 계획 채택, 볼일 완료와 다음 귀가의 재사용 여부 확인
