# 휴대폰과 차량 연결

차량에서 연결 QR을 열고 휴대폰에서 주소를 확인하면 볼일 제안을 차량 수신함으로 보낼 수 있다
연결은 15분 동안 유지하며 발신·수신 권한을 따로 사용한다

## 사용 흐름

- 차량의 휴대폰 연결에서 함께 공유할 볼일 한 건을 확인하고 연결 시작
- 공유할 볼일이 있으면 그 장소와 체류·도보·준비·마감 조건만 전달
- 휴대폰에서 QR 링크를 열거나 연결 QR 이미지를 선택하고 연결 주소 확인 후 접속
- 휴대폰의 주소로 새 볼일에서 주소 검색·후보 확인·픽업 또는 장보기 선택
- 차량이 공유한 볼일이 있으면 조건 정해 보내기에서 바로 편집
- 체류·도보·준비·마감 조건을 확인하고 필요한 값만 변경
- 보낼 조건 확인에서 장소·조건을 검토하고 연결된 차량으로 보내기
- 차량 수신함 보관을 확인한 뒤 운전자가 받은 볼일에서 검토하고 계획에 반영

차량의 집·동승자 하차 장소·전체 계획은 연결에 포함하지 않는다
공유할 장소 없이 연결할 수도 있으며, 휴대폰에서 새 주소를 검색해 제안을 만들 수 있다
제안을 수신하거나 반영해도 길안내는 바뀌지 않으며 이후 경로를 다시 비교한다

휴대폰 편집은 선택한 볼일 한 건을 기준으로 동작한다
마감은 받은 시각 유지·마감 없음·표시된 날짜 중에서 선택하며 편집 중 날짜가 바뀌어도 선택한 날짜를 유지한다
확인 화면의 조건 수정은 작성한 값을 다시 열고, 다른 볼일은 수신함으로 돌아간다
입력값·원본 유효시간은 새 제안을 만들 때 검증하고 차량의 계획 반영은 운전자가 따로 승인한다

## 주소로 볼일 만들기

Android 13 이상에서 기기의 Geocoder로 주소를 검색한다
검색 버튼을 눌렀을 때만 시·구·도로명·건물번호를 조회하며 별도 API 키와 기기 위치 권한은 사용하지 않는다
최대 다섯 후보의 전체 주소를 표시하고 지도에서 위치 확인으로 설치된 지도 앱을 열 수 있다
주소 검색 결과는 매장 식별자나 출입구·정차 가능 여부를 보증하지 않으므로 사용자가 장소를 확인한 뒤 선택한다

- 검색어를 바꾸면 이전 후보와 선택을 지우고 새 검색 결과에서 다시 선택
- 화면을 벗어날 때 진행 중 검색은 취소하고 완료된 후보는 지도 앱 확인 후 돌아와도 유지
- 응답은 10초 동안 기다리며 취소·시간 초과 뒤 늦게 도착한 결과는 화면에 반영하지 않음
- Geocoder에는 공개 취소 API가 없어 이전 요청이 끝나기 전에는 새 요청을 쌓지 않음
- 서비스가 응답하지 않으면 해당 프로세스에서 검색 대기 상태가 이어질 수 있음
- 기기가 검색 서비스를 제공하지 않거나 지원 버전보다 낮으면 사유 표시
- 주소로 만든 볼일은 별도 출처로 관리하며 받은 볼일 수신함에 임의로 추가하지 않음
- 새 주소의 기본 체류시간은 픽업 10분·장보기 20분, 편도 도보 2분이며 사용자가 확인 후 변경
- 새 주소에는 준비 완료와 마감 시각을 임의로 채우지 않으며 작성 시작 후 24시간이 지나면 재작성

검색 후보에는 주소와 좌표만 사용하고 차량 내비의 POI ID를 만들어 넣지 않는다
내비 반영 확인도 기존 좌표 일치 기준을 유지하며 응답에 좌표가 없으면 확인된 안내로 처리하지 않는다
API 계약은 [Geocoder](https://developer.android.com/reference/android/location/Geocoder)와 [GeocodeListener](https://developer.android.com/reference/android/location/Geocoder.GeocodeListener) 참고

## 전송 상태

| 상태 | 의미 |
| --- | --- |
| `QUEUED` | 서버가 전송을 접수했고 차량 수신함 보관을 기다리는 상태 |
| `STORED` | 차량 수신함의 저장 성공을 확인한 상태 |
| `REJECTED` | 차량이 만료·형식·충돌 등의 이유로 제안을 보관할 수 없는 상태 |

`STORED`는 운전자의 승인이나 차량 내비 반영을 뜻하지 않는다
응답을 받지 못한 전송은 같은 메시지 ID와 원래 제안 링크로 재시도한다
입력 조건을 바꾸면 이전 내보내기를 지우고 새 제안을 만들게 한다

## 수신과 저장

- 차량 앱이 `STARTED` 상태인 동안 대기 제안을 조회하고 화면으로 돌아오면 재개
- 주행 제한 중에는 연결·검토창을 닫고 수신함 저장만 수행
- `ProposalLinkCodec`과 기존 수신함 규칙으로 제안 내용·버전·유효시간 검증
- 새 제안과 중복 제안 모두 수신함 `commit()` 성공을 확인한 뒤 `STORED` 응답
- 저장 실패와 수신함 상한 초과는 응답을 보류해 다시 받을 수 있게 유지
- 형식 오류·만료·같은 버전의 내용 충돌은 `REJECTED`로 응답
- 받은 볼일은 기기 안에 저장하고 기존 제안 유효시간·완료 마감 검증 유지

연결 토큰·연결 QR·전송 중 상태는 메모리에서만 관리한다
앱 프로세스나 화면이 재생성되면 새 QR로 연결하며 이미 저장한 수신함은 복원한다
휴대폰의 검색어·선택한 주소·편집 조건·전송 확인 제안은 화면 재생성 후 복원한다
진행 중이던 검색은 자동으로 재요청하지 않고 검색어를 유지하며 다시 검색할 수 있게 한다
작성 시작 시각과 기준 날짜를 유지하고 받은 볼일은 수신함의 동일 버전·유효시간을 다시 확인한다
연결 종료는 서버 응답을 받은 뒤 반영하고 실패하면 재시도할 수 있게 연결 상태를 유지한다
종료·인증 실패가 확인되거나 유효시간이 지나면 연결을 정리하며 휴대폰의 작성 조건과 제안 링크는 남긴다
서버는 메모리만 사용하므로 서버 종료 시 연결과 아직 전달되지 않은 제안은 사라진다

## 개발 실행

서버 실행과 HTTP 계약은 [로컬 중계 서버](../tools/proposal-relay/README.md) 참고
기본 포트는 `48680`이다

같은 개발 컴퓨터의 AVD 두 대에서 연결할 때는 공개 연결 주소를 에뮬레이터가 접근할 수 있는 값으로 지정한다

```sh
python3 tools/proposal-relay/relay.py --host 127.0.0.1 --public-url http://10.0.2.2:48680
```

LAN의 휴대폰과 연결할 때는 아래 예시의 `192.168.0.10`을 개발 컴퓨터의 사설 IP로, `192.168.0.20`을 연결할 휴대폰의 사설 IP로 바꾼다

```sh
python3 tools/proposal-relay/relay.py --host 0.0.0.0 --public-url http://192.168.0.10:48680 --allow-client 127.0.0.1 --allow-client 192.168.0.20
```

- LAN 리스너는 `--allow-client`로 접속할 기기의 IPv4 주소를 지정해야 시작
- 위 예시는 로컬 AVD와 지정한 휴대폰만 허용하며 다른 소켓은 HTTP 처리 전에 종료
- 호스트 이름·대역·전체 허용 주소는 접속 허용값으로 사용하지 않음
- 휴대폰 IP가 바뀌면 서버를 다시 실행하고 새 QR로 연결
- IP 제한과 기존 발신·수신 토큰 검증을 함께 사용

차량 앱이 접속할 주소는 Gradle 속성 `proposalRelayBaseUrl`로 설정한다
디버그 기본값은 `http://10.0.2.2:48680`, 릴리스 기본값은 빈 값이다
서버의 `publicBaseUrl`은 휴대폰이 접속할 주소이며 차량용 주소와 다를 수 있다

```sh
./gradlew :app:assembleDebug -PproposalRelayBaseUrl=http://10.0.2.2:48680
```

- 디버그의 HTTP 접속은 앱 클라이언트에서 localhost·loopback·10/8·172.16/12·192.168/16의 사설 주소로 제한
- 릴리스는 HTTPS만 허용하며 연결 주소·토큰을 저장소나 로그에 기록하지 않음
- 연결 QR에는 발신 권한만 포함하고 차량의 수신 권한은 메모리에만 유지
- 기본 검증 역할은 차량 수신자와 휴대폰 발신자로 구분
- 현재 대상 API 36의 로컬망 접근은 `INTERNET` 권한을 사용하며 대상 API 37로 올릴 때 별도 권한 경계 재검토

로컬망 권한 기준은 [Android 공식 문서](https://developer.android.com/privacy-and-security/local-network-permission) 참고
