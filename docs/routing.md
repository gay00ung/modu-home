# 도로 경로 서버

가는김에와 함께 귀가는 현재 차량 위치에서 집 직행과 가능한 방문 순서의 도로 경로를 조회한다
도로별 일방통행과 회전 조건이 반영된 구간 시간을 사용하며, 한 목적지의 도착시간을 다른 목적지에서 빼서 구간 시간을 만들지 않는다
함께 귀가의 세 정차는 차량 내비의 두 경유지 제한에 맞춘 안내 단계별 경로로 계산한다

## 로컬 실행

macOS에서는 Homebrew의 OSRM을 사용할 수 있다
지도 데이터와 전처리 결과는 저장소 밖에 둔다

```sh
brew install osrm-backend
ROUTING_DATA="$HOME/.cache/modu-home-routing"
mkdir -p "$ROUTING_DATA"
curl --fail --location --output "$ROUTING_DATA/south-korea-latest.osm.pbf" https://download.geofabrik.de/asia/south-korea-latest.osm.pbf
```

[Geofabrik 대한민국 데이터](https://download.geofabrik.de/asia/south-korea.html)의 다운로드 체크섬과 파일을 비교한 뒤 같은 OSRM 버전으로 세 단계를 수행한다
자동차 프로필을 사용하므로 보행 경로로 해석하지 않는다

```sh
osrm-extract -p "$(brew --prefix)/share/osrm/profiles/car.lua" -t 2 -d osmosis "$ROUTING_DATA/south-korea-latest.osm.pbf"
osrm-partition -t 2 "$ROUTING_DATA/south-korea-latest.osrm"
osrm-customize -t 2 "$ROUTING_DATA/south-korea-latest.osrm"
osrm-routed --algorithm MLD --ip 127.0.0.1 --port 5001 --threads 2 --mmap --max-viaroute-size 8 --max-table-size 16 "$ROUTING_DATA/south-korea-latest.osrm"
```

- 서버는 실행한 터미널에서 유지하고 종료할 때 Ctrl+C 사용
- `debug` APK의 기본 주소는 AVD에서 호스트를 가리키는 `http://10.0.2.2:5001`
- 다른 서버는 Gradle의 `routingBaseUrl` 속성으로 지정
- `release`는 HTTPS 서버 주소를 지정해야 도로 경로 조회 사용 가능
- 서버에 전달되는 내용은 선택한 장소의 좌표이며 배포 서버의 보관·접근 정책을 개인정보 안내에 반영

```sh
./gradlew :app:assembleRelease -ProutingBaseUrl=https://routing.example.com
```

위 도메인은 설정 형식을 보여주는 예시다
서비스 서버의 실제 HTTPS 주소로 바꾼다

Linux 서버에 배치할 때는 [HTTPS 서버 실행](../tools/service-stack/README.md)의 이미지 안에서 전처리한다
OSRM 전처리 파일은 운영체제에 종속되므로 macOS에서 생성한 파일을 Linux에 복사해 사용하지 않는다
새 디렉터리에 원본 PBF를 준비하고 추출·분할·가중치 계산을 마친 뒤 읽기 전용으로 연결한다

## 시간 한도를 유지하는 가는김에 대안

픽업·장보기를 함께 비교한 상태에서 대안 비교를 누르면 NaviHelper의 현재 차량 위치를 다시 읽는다
집 직행을 공통 기준으로 다음 다섯 경로를 도로 서버에 조회한다

| 비교 범위 | 요청 순서 |
| --- | --- |
| 집 직행 | 현재 위치 → 집 |
| 두 볼일 | 현재 위치 → 픽업 → 장보기 → 집 |
| 두 볼일 | 현재 위치 → 장보기 → 픽업 → 집 |
| 픽업만 | 현재 위치 → 픽업 → 집 |
| 장보기만 | 현재 위치 → 장보기 → 집 |

중간 정차를 지운 대안은 기존 경로에서 구간을 빼서 만들지 않는다
같은 지도 버전의 다섯 응답이 모두 확인돼야 비교를 갱신하고, 실패하거나 취소되면 일부 응답만 적용하지 않는다
두 대안의 집 도착·추가시간은 같은 집 직행 응답과 기존 시간 한도를 사용해 계산한다
조회 완료·선택 시각에 출발·마감을 다시 계산하되 원래 응답의 조회시각은 유지한다
5분을 넘긴 응답이나 다른 입력에 속한 선택은 거부하고 다시 조회한다
선택한 대안의 경로만 기존 계획 형식으로 저장하며 차량 내비 전송은 출발 전 확인 이후에 수행한다

## 함께 귀가 경로 조합

동승자 2명과 볼일 1건은 여섯 방문 순서를 만든다
각 순서를 `A → B → E`라고 하면 다음 두 경로를 조회한다

| 조회 | 요청 순서 | 계산에 사용하는 구간 |
| --- | --- | --- |
| 출발 단계 | 현재 위치 → A → B → 운전자 집 | 현재 위치 → A |
| A 완료 후 단계 | A → B → E → 운전자 집 | A → B, B → E, E → 운전자 집 |

출발 단계의 B → 집 구간은 전체 계획의 귀가시간에 사용하지 않는다
첫 정차를 마친 뒤 볼일을 포함한 다음 안내로 바뀌는 계획이기 때문이다
두 경로에서 선택한 구간을 순서대로 연결해 해당 계획의 네 주행 구간을 만든다
정차가 두 곳 이하면 출발지부터 집까지 한 번에 조회한다

세 정차의 여섯 순서는 각 두 건, 집 직행은 한 건으로 총 13건의 경로 응답을 검증한다
이는 시간 비교를 위한 도로 서버 조회이며 NaviHelper에 세 경유지를 한꺼번에 보내는 요청이 아니다
이전의 지점 쌍별 예상시간이나 다른 순서의 구간시간으로 빠진 응답을 채우지 않는다

## 계산과 실패 처리

- 각 경로의 구간 시간·거리와 경유 순서가 요청에 대응하는지 검증
- 도로 연결점과 요청 장소의 거리가 250m를 넘으면 해당 응답 거부
- 경로 일부가 누락되거나 서로 다른 지도 버전이면 비교 결과를 만들지 않음
- 구간 이동시간은 1분 단위 올림하고 체류·왕복 보행시간 합산
- 함께 귀가는 동승자별 하차 정차 1분을 더하고 하차 뒤 볼일은 해당 사람의 도착시간에서 분리
- 모든 순서의 응답이 모인 뒤 비교 화면 표시
- 서버 연결 실패를 수동 예상시간으로 바꿔 표시하지 않음
- 함께 귀가는 모든 순서의 요청 지점·구간 순서·사용한 구간 인덱스를 검증하고 같은 지도 버전과 5분 이내 응답만 비교
- 응답 시각과 지도 버전을 함께 저장하고 출발 전에 5분이 넘은 비교 결과는 현재 위치에서 재조회
- 가는김에는 비교 완료·실제 출발 요청 시각으로 도착·마감을 다시 계산하며 원래 도로 응답은 새 응답으로 처리하지 않음
- 분 단위 계획의 출발 시각은 다음 정각 분으로 올림하고 마감의 실제 날짜와 저장한 시간대를 유지
- 선택한 순서의 조건이 맞지 않으면 비교로 돌아가고 오래된 응답은 입력에서 다시 조회
- 분 단위로 표현할 수 없는 시간대 전환이 48시간 안에 있으면 자동 출발 계산 중단
- 함께 귀가는 출발 버튼을 누른 시각으로 도착·마감만 다시 계산하고 원래 조회시각과 데이터 버전 유지

함께 귀가의 진행·완료 기록은 오래된 경로 관측도 당시 계획의 근거로 보관한다
복원은 새 조회가 아니며, 진행 중에는 내비의 남은 순서를 다시 읽고 계획과 대조한다

## 출처와 범위

OSRM의 자동차 프로필과 OpenStreetMap 도로망에 따른 예상시간이며 실시간 교통은 포함하지 않는다
NaviHelper의 현재 위치→목적지 예상시간 조회는 차량 내비가 제공하는 별도 결과다
두 결과를 같은 교통 조건의 시간처럼 섞지 않는다

가는김에는 계획을 차량 내비로 전달한 뒤 `getDestinationInfo`와 `getWaypointInfo`의 남은 시간·거리를 읽는다
가는김에의 진행 화면은 현재 안내의 다음 장소와 집까지 남은 주행시간을 보여주며, 체류·도보시간은 따로 표시한다

- 목적지와 남은 경유 순서를 조회 전후 대조하고 응답이 같은 안내에 속하는지 확인
- 이미 지난 경유지가 앞에서부터 제거된 경우만 허용
- 각 지점까지의 누적 시간을 더하거나 빼서 다른 구간 시간으로 사용하지 않음
- 화면이 보일 때 조회하고 확인된 안내는 응답 후 30초 대기해 갱신
- 초기 15초 안에 안내를 확인하지 못하면 응답 후 2초 대기해 재조회하며 이후에는 30초 간격 유지
- 60초 지난 응답은 표시하지 않음
- 재탐색·경유지·목적지·경로 옵션 변경 시 이전 시간 무효화
- 누락·음수·역전된 시간과 거리는 이전 계획 시각으로 대신하지 않음
- SDK가 측정 시각을 제공하지 않으므로 수신 시각과 교통 정보 갱신 시각을 구분

함께 귀가의 진행 화면은 전체 계획의 다음 정차·완료 개수와 실제 내비 반영 상태를 구분한다
도로 비교에서 계산한 도착시각을 실시간 내비 잔여시간으로 바꾸어 표시하지 않는다
NaviHelper 확인 방식과 단계 전환은 [차량 내비 설정과 실행](vehicle-navigation.md)에 정리했다

Connect 2.1 AVD에서는 실제 길안내 중에도 `isRouting=false`가 수신됐다
안내 여부는 명시적인 `ROUTE_GUIDING`·`SIMULATION_GUIDING` 모드와 장소·순서 대조로 확인한다
앱의 안내 진단 로그에는 모드·플래그·시간·거리만 남기며 장소명·좌표는 기록하지 않는다
