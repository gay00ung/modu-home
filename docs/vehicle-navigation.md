# 차량 내비 설정과 실행

가는김에의 볼일과 함께 귀가의 하차·볼일 순서를 Pleos 차량 내비로 전달한다
전체 귀가 계획은 운전자 집에서 끝난다
두 흐름 모두 내비에서 장소를 확인할 수 있는 구간으로 나누고 남은 순서를 이어 안내한다

## 실행 환경

- Pleos Connect Emulator 2.1.0, Android API 34
- Mac Apple Silicon은 ARM64 시스템 이미지 사용
- Pleos Connect 기기 프로필, RAM 4GB, Cold boot
- 한국 기준 시각으로 계획하려면 AVD 시간대를 Asia/Seoul로 설정
- NaviHelper SDK 3.0.5와 공식 Maven 저장소 사용

[Pleos Emulator 설치 가이드](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)의 시스템 이미지 저장소를 SDK Update Sites에 추가한 뒤 AVD를 생성한다
SDK 라이선스에 동의한 환경에서 설치한다

차량 AVD는 화면을 사용하는 사용자와 시스템 사용자가 다를 수 있다
단말 목록과 현재 사용자 ID를 확인하고 같은 사용자에 앱을 설치·실행한다

```sh
adb devices -l
adb -s emulator-5554 shell am get-current-user
```

현재 사용자가 10인 경우

```sh
adb -s emulator-5554 install -r -t --user 10 app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 shell am start --user 10 -n io.moduhome.app/.MainActivity
```

## 장소 선택

- 차량 내비에서 필요한 장소를 검색하거나 즐겨찾기에 저장
- 모두 집으로의 차량 화면에서 운전자 집·동승자 하차·픽업·장보기 장소 선택
- 저장 장소와 최근 목적지는 NaviHelper 응답으로 불러오기
- 선택한 장소의 이름·주소·좌표·장소 ID를 계획과 함께 기기 안에 저장
- 가는김에 상세 입력에서 장소명을 직접 바꾸면 기존 좌표 연결 해제
- 픽업 장소를 바꾸면 수령 준비 여부도 다시 확인
- 함께 귀가의 하차 장소를 바꾸면 집 앞 직접 하차와 안전한 정차·하차 연결을 다시 확인

함께 귀가의 집 앞 확인은 사용자의 직접 확인을 출처·시각과 함께 저장한다
확인 전에는 하차 후 이동을 0분으로 계산하거나 하차 장소가 적합하다고 처리하지 않는다

차량 내비의 출발지는 현재 차량 위치를 사용한다
도로 경로 서버가 반환한 구간 주행시간을 올림해 보행·체류시간과 합산한다
보행·체류시간은 선택한 조건이며 실시간 교통은 포함하지 않는다
출발 전 비교 데이터가 5분을 넘으면 현재 위치에서 다시 비교한다
함께 귀가는 출발 버튼을 누른 시각으로 조건을 다시 검사하며 원래 경로 조회시각을 바꾸지 않는다

## 경로 전달과 확인

- 계획 비교에서 선택한 순서 중 해당 단계의 최대 두 경유지를 목록으로 변환
- 첫 경유지는 `FIRST`, 두 번째 경유지는 `SECOND`로 지정하고 해당 안내 구간의 목적지를 전달
- `requestRouteWithWaypoints()` 호출 후 목적지·경유지·안내 상태를 다시 조회
- 차량에서 반환한 경유지 목록의 순서를 유지해 계획과 비교
- SDK 전송 결과는 두 번의 연속 조회에서 목적지·경유 순서가 일치하고 길안내 중일 때 반영을 확인한 것으로 처리
- 요청 접수만으로 반영을 확정하지 않으며 전송 오류·응답 시간 초과는 미확인 상태로 표시하고 재시도 가능
- 진행 화면의 차량 내비 다시 확인으로 현재 안내 경로 조회

장소 ID가 양쪽 응답에 있으면 제공자와 ID를 우선 비교한다
장소 ID가 없는 경우에는 좌표의 25m 이내 오차로 확인한다
AVD에서 경유지 좌표를 0,0으로 반환하는 경우는 좌표 없음으로 처리하며 요청 좌표로 채우지 않는다
장소 ID가 없는 새 주소는 좌표를 읽을 수 있는 구간 목적지로 보낸다
이름만 일치하는 경유지를 반영 완료로 처리하거나 임의의 장소 ID를 만들지 않는다

## 가는김에 단계별 안내

완료한 볼일을 전체 계획에서 먼저 제외한 뒤 이번 안내 구간을 만든다
픽업 A와 장보기 B가 모두 장소 ID 없는 주소라면 다음과 같이 연결한다

| 확인한 완료 | 이번 안내 목적지 | 마지막 집 |
| --- | --- | --- |
| 없음 | A 픽업 주소 | 운전자 집 유지 |
| A 픽업 | B 장보기 주소 | 운전자 집 유지 |
| B 장보기 | 운전자 집 | 운전자 집 |

- 출발 확인과 완료 확인에 이번 안내 순서와 마지막 집을 표시
- 이번 목적지가 볼일이면 SDK 남은 시간을 이번 구간의 주행시간으로 표시하고 집까지의 시간과 구분
- 시작·완료 기록의 저장을 확인한 뒤 SDK에 다음 구간 전달
- 완료와 재개 확인은 전체 계획·현재 내비 응답·경로 변경 번호·입력 제한 상태에 연결
- 확인 뒤 안내나 계획이 바뀌면 이전 승인으로 적용하지 않으며 화면을 떠나면 조회와 확인 취소

현재 내비가 남은 계획의 앞 경유지를 이미 제거했다면 해당 안내를 유지하고 실제 완료한 볼일만 기록한다
이미 지난 경유지를 다시 추가하지 않으며, 순서 중간의 경유지가 빠지거나 목적지가 바뀐 안내는 같은 계획으로 취급하지 않는다
기존 POI 경유지의 안내가 종료된 상태에서는 사용자가 완료만 기록할 수 있다
안내를 다시 시작하려면 현재 경로와 남은 순서를 별도로 확인하고 승인한다
새 주소가 이번 구간의 목적지라면 실제 볼일 완료를 확인한 뒤 다음 주소나 집 안내를 연결한다

## 함께 귀가 단계별 안내

동승자 최대 2명과 볼일 1건은 전체 세 정차까지 보관한다
선택한 전체 순서가 `A 하차 → B 하차 → E 볼일 → 운전자 집`이고 세 정차에 장소 ID가 있으면 다음과 같이 안내한다

| 단계 | 경유 순서 | 목적지 |
| --- | --- | --- |
| 최초 전송 | A → B | 운전자 집 |
| A 완료 확인 후 | B → E | 운전자 집 |
| B 완료 확인 후 | E | 운전자 집 |
| E 완료 확인 후 | 없음 | 운전자 집 |

E가 휴대폰에서 검색한 새 주소라면 목적지 좌표로 확인할 수 있도록 다음 구간을 사용한다

| 단계 | 경유 순서 | 이번 안내 목적지 |
| --- | --- | --- |
| 최초 전송 | A → B | E 볼일 주소 |
| A 완료 확인 후 | B | E 볼일 주소 |
| B 완료 확인 후 | 없음 | E 볼일 주소 |
| E 완료 확인 후 | 없음 | 운전자 집 |

- 첫 정차나 두 번째 정차가 새 주소인 경우에도 그 주소까지 안내하고 완료 후 남은 순서 연결
- 출발 전 차량 화면에 이번 구간과 이후 집 안내를 표시
- 운전자 집을 안내 구간 목적지와 별도로 보관하고 복원 시 원래 집과 대조
- 이전 저장 형식은 기존 경유 순서를 먼저 검증한 뒤 완료 기록을 유지하고 새 구간을 재확인 대기로 복원

- 각 하차·볼일 완료는 입력이 허용된 정차 상태에서 사용자가 확인
- 완료 사실과 다음에 반영할 경로를 먼저 저장하고 저장 결과 확인 후 SDK 작업 수행
- 현재 안내가 이미 필요한 경유 순서라면 재전송 없이 조회 결과로 확인
- 앞 단계의 안내를 유지하고 있으면 남은 정차를 포함한 다음 안내로 갱신
- 현재 안내가 다른 목적지·순서로 바뀌었다면 변경 확인창에서 승인받은 안내만 요청
- 변경 승인 뒤 차량 내비 경로가 바뀌면 기존 승인으로 덮어쓰지 않음
- 실패한 다음 단계는 반영 대기로 유지하고 완료한 정차를 다시 추가하지 않음

내비가 앞 경유지를 이미 제거했더라도 하차나 볼일 완료를 자동 기록하지 않는다
실제 길안내가 반영 대기 중인 해당 단계의 앞 경유지 1~2곳만 제외한 순서와 목적지까지 정확히 일치할 때 완료 확인으로 이어간다
한 곳은 ‘이미 하차했나요?’ 또는 ‘이미 볼일을 마쳤나요?’, 두 곳은 ‘지난 두 정차 확인’으로 표시한다
확인창에 대상 장소와 하차·볼일 종류, 실제 내비의 남은 경유지와 이번 안내 목적지를 표시하며 두 곳은 모두 마쳤을 때 함께 확인한다
승인 뒤 같은 안내·계획·진행·입력 제한 상태인지 다시 확인하고, 완료 기록과 다음 안내의 저장에 성공한 뒤 남은 순서를 반영한다
확인창을 닫거나 재조회에서 안내·진행·입력 제한의 변경이 확인되면 완료 기록을 추가하지 않는다

SDK 요청으로 차량 내비 화면이 열려 앱이 일시 중지되면 앱의 진행 중인 조회·확인 작업을 취소하고 늦은 결과를 버린다
그 사이 SDK 안내가 바뀌었을 수 있으므로 앱에 돌아오면 현재 안내를 읽어 해당 단계와 대조한다

## 함께 귀가의 현재 도착 예상

- 전체 방문 순서를 비교할 때의 도로망 예상과 진행 중 차량 내비의 남은 시간을 구분
- 이번 안내와 남은 정차 순서가 일치할 때 다음 정차 하나의 시간만 표시
- 경유지의 남은 시간은 차량부터 해당 지점까지의 누적값으로 사용하며 서로 더하지 않음
- 동승자 도착은 남은 주행에 하차 정차와 하차 후 이동을 더해 도착 희망과 비교
- 볼일 완료는 남은 주행에 가게까지 편도 도보와 체류를 더해 마감과 비교
- 중간 정차를 모두 직접 완료한 뒤 운전자 집 도착 예상 표시
- 희망·마감 초과와 계획보다 5분 이상 늦어지는 예상을 표시하며 경로를 자동 변경하지 않음
- 주행 제한 중에도 시간은 읽기 전용으로 조회하고 편집·완료 확인은 잠금 유지
- 60초를 넘긴 조회 결과, 다른 안내, 완료 전 구간의 결과와 화면 이탈 전 결과는 표시하지 않음

SDK의 조회 응답 시각은 실제 교통 정보의 측정 시각과 다르다
차량 내비 기준 예상이며 이후 모든 정차를 포함한 전체 귀가 시각으로 확장하지 않는다

## 복원과 연결 실패

- 재실행 시 전체 계획과 하차·볼일 완료 기록을 검증하고 실제 내비는 재확인 대기로 복원
- 복원·화면 재진입만으로 새 경로를 전송하지 않음
- 남은 순서 재시도는 현재 안내를 먼저 읽고 필요한 변경을 확인한 뒤 수행
- SDK 연결 실패는 진행 기록을 유지한 채 내비 다시 연결로 복구
- 모든 정차를 완료했다면 내비 안내 종료 여부와 별개로 사용자가 집 도착을 확인해 귀가 기록 마무리

새 주소가 이번 구간의 목적지이고 그 앞의 경유지를 모두 완료했다면, 길안내가 없는 상태에서도 해당 정차의 완료를 직접 확인할 수 있다
차량의 `볼일 완료 직접 확인` 또는 `하차 완료 직접 확인`을 누르면 장소를 다시 표시한다
길안내 종료를 도착으로 간주하지 않으며 사용자가 실제 완료를 승인한 경우에만 기록한다
승인 후 현재 내비를 다시 읽고 안내·전체 계획·완료 기록·입력 제한이 바뀌지 않았는지 대조한 뒤 다음 구간을 요청한다
확인창을 닫거나 화면을 떠나면 해당 승인을 보관하지 않는다

계획 기록을 중단해도 차량 내비의 길안내는 유지한다
함께 귀가의 세 정차는 앱이 각 단계의 확인을 이어가야 전체 순서로 연결된다

## SDK 권한과 수명

- `pleos.car.permission.NAVI_ROUTE`: 저장 장소·최근 목적지·안내 정보 조회
- `pleos.car.permission.NAVI_ROUTE_SEARCH`: 목적지와 경유지를 포함한 경로 요청
- 자동차 환경에서 SDK를 초기화하고 화면이 해제되면 리스너 제거 후 SDK 해제
- SDK 타입은 `data/navigation` 안에서 다루고 화면과 계산 코드에는 전달하지 않음

- [SDK 의존성 설정](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/importing-sdk)
- [경유지를 포함한 경로 요청](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/route-with-waypoints)

## 차량 입력과 음성

- 현재 디스플레이의 CarUxRestrictions를 구독하고 제한 상태를 모르면 편집 잠금
- 입력 제한이 생기면 장소 선택·제안 검토·음성 창을 닫고 계획은 보존
- 가는김에 음성 입력은 SpeechToText 3.3.1의 ON_DEVICE 모드와 한국어로 설정
- debug 빌드에서 음성 버튼을 표시하고 release 기본값은 비활성화하며 `-PenableVehicleVoice`로 명시적 설정
- `pleos.car.permission.STT_SERVICE` 권한 선언
- 말로 선택 버튼에서만 인식을 시작하고 알아들은 명령은 적용 버튼으로 확인
- Activity가 일시 중지되면 음성 인식을 중단하고 늦은 결과는 버림
- 중단 콜백이 오지 않으면 해제 후 실패 상태를 유지하며 같은 세션에서 재요청 금지
- 일반 Activity를 주행 허용으로 선언하지 않으며 플랫폼 차단 정책 유지

음성 인식·종료 응답은 대상 차량의 SpeechToText 서비스에서 확인한다

[차량 화면 기준](vehicle-ux.md)에 글자·버튼 크기와 제한 중 표시 원칙을 정리했다
