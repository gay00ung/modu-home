# 차량 화면 기준

모두 집으로는 센터 디스플레이에서 장소와 방문 순서를 고르는 앱이다
기본 화면에서 주소·좌표·일곱 구간의 시간을 직접 입력하게 하지 않는다
집과 들를 곳을 선택하면 현재 차량 위치에서 경로를 조회한다

## 선택 흐름

- 집과 픽업·장보기 장소 선택
- 체류시간과 더 걸려도 괜찮은 시간을 큰 프리셋 버튼으로 선택
- 두 순서의 집 도착 계획과 추가시간을 나란히 비교
- 선택한 순서를 한 번 확인하고 차량 내비로 전달
- 정차한 뒤 볼일 완료를 확인하고 마지막에 집 도착 기록

비교·확인 화면의 시간에는 교통 제외 기준을 숫자 바로 위에 표시한다
출발 후에는 차량 내비에서 확인한 다음 장소와 집까지 남은 주행시간을 표시한다
체류·도보시간은 별도이며 안내 변경이나 조회 실패 시 이전 시간을 현재 시간으로 유지하지 않는다

장소를 선택하지 않았거나 경로 응답이 없으면 예시 장소·기본 예상시간으로 차량 계획을 만들지 않는다
마감과 보행시간 같은 세부 조건은 입력 제한이 해제된 상태의 상세 화면에서 설정한다

## 크기와 정보량

| 항목 | 기준 |
| --- | --- |
| 화면 제목 | 40sp |
| 목적지와 본문 | 28~32sp |
| 주요 시간과 다음 목적지 | 48~52sp |
| 보조 정보 | 22sp 이상 |
| 조작 영역 | 80dp 이상 |
| 주요 실행 버튼 | 96dp 이상 |
| 장소·음성 선택창 | 넓은 차량 영역, 고정 닫기·확인 버튼 |

- 중요한 오류는 상단에 표시하고 스크롤 아래로 숨기지 않음
- 한 화면에서 해야 할 주요 행동은 하단 버튼 하나로 표시
- 긴 장소명은 줄 수를 제한하고 선택창에서 전체 이름·주소 확인
- 터치 영역과 글자는 실제 AVD 앱 영역에서 확인하고 전체 디스플레이 크기로만 판단하지 않음
- 운전석 거리에서의 물리적 글자 크기는 실제 차량 디스플레이에서 별도 확인

## 주행 제한

차량 기어를 추측해 잠그지 않고 현재 디스플레이의 `CarUxRestrictions`를 따른다
연결 전·오류·주행 제한 중에는 계획 편집을 잠근다

- 상세 입력, 장소 목록, 제안 승인, 완료 처리, 내비 전송, 음성 입력 차단
- 열린 선택창을 닫고 현재 계획 보존
- 제한 중 앱 내부 화면은 스크롤·입력 없이 최대 세 항목만 표시
- 플랫폼이 내려준 문자열 길이·항목 수·메뉴 깊이 제한 반영
- 일반 Activity에는 `distractionOptimized`를 선언하지 않고 OS의 주행 차단 유지
- 실제 길 안내는 선택한 경로를 받은 차량 내비가 담당

큰 글자만으로 주행 중 사용 승인을 대신할 수 없다
주행 중 앱 자체를 계속 표시하는 배포는 Pleos의 앱 유형·심사 조건을 확인한 뒤 판단한다

## 음성

음성 입력은 `enableVehicleVoice=true`로 빌드한 검증 환경에서 사용한다
기본 빌드에서는 터치 선택을 제공한다

- 말로 선택 버튼을 누를 때만 차량 온디바이스 인식 시작
- ‘장도 보고 갈래’, ‘픽업 빼줘’, ‘추가 20분’, ‘수령 준비됐어’처럼 한 가지 요청 처리
- 자유 주소나 복합 문장은 임의로 해석하지 않고 지원 범위 안내
- 인식한 명령은 큰 확인창에 표시하고 적용을 눌러 계획에 반영
- 화면이 일시 중지되거나 입력 제한이 생기면 중단 요청
- 종료 콜백을 최대 3초 기다린 뒤 리스너·SDK를 해제하고 미확인 시 재요청 차단
- 이전 요청의 결과가 새 확인창에 나타나지 않도록 요청 세대 확인
- 음성과 인식 문장은 저장하거나 로그로 남기지 않음
